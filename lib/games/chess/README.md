# 中国象棋（chess）

楚河汉界双人对弈，将死对方取胜。棋盘、棋子与河界全部由 `CustomPainter`
自绘（无图片素材），棋子为米色圆面 + 红黑描边 + 繁体汉字。支持本地双人
同屏对弈与局域网 2 人联机（房主权威校验走子 + 棋类通用悔棋/认输协商）。

## 文件结构

| 目录/文件 | 职责 |
| --- | --- |
| `models/` | `chess_piece`（棋子纯数据模型：类型/颜色/繁体字与素材色；编码沿用 Xiangqi FEN 惯例 KABNRCP，红大写黑小写）、`chess_board`（可变棋盘容器：开局局面、applyMove/revertMove、90 格紧凑编码）、`chess_game_state`（存档模型：盘面编码 + 轮次 + 走子序列，`version = 1`） |
| `services/` | `chess_rules`（规则引擎：纯静态逻辑，本地页与联机控制器共用同源判定）、`chess_online_controller`（联机控制器：走子校验广播 + 悔棋/认输协商钩子）、`chess_storage`（存档服务，`gameId = '中国象棋'`） |
| `pages/` | `chess_page` 本地对局页（选子走子、将军提示、终局弹窗、退出存档与恢复、建房入口）、`chess_online_page` 联机对局页（选子预选、胜负文案组装，骨架与协商委托共享层） |
| `widgets/` | `chess_board_canvas`（棋盘画布：本地与联机共用，等比缩放 + 点击命中 + 走子滑动动画）、`chess_board_geometry`（逻辑格坐标 ↔ 屏幕像素换算，绘制与手势共用，支持整盘 180° 翻转）、`chess_board_painter`（底板/线路/河界/九宫/炮兵位标记/棋子/高亮绘制）、`chess_board_view`（本地对局视图组装）、`chess_setup_view`（模式设置与恢复入口） |

## 核心流程

1. **走子交互**：点己方棋子选中并缓存合法走法 → 点合法落点进入预选
   （确认行「取消/确认」）→ 确认后搬运棋子、历史入列（记录被吃子）、轮换。
2. **规则引擎两层走法**：`movesFor` 生成伪合法走法（棋子自身规则 + 不吃己子）；
   `legalMovesFor` 过滤「走后己帅被将军」与「将帅照面」——用 applyMove/revertMove
   试走模拟。七类棋子规则齐全：炮吃子须隔恰好一个炮架、马蹩腿、相塞眼不过河、
   兵过河前只进、过河可横、永不后退。
3. **将军与终局**：`isSquareAttacked` 覆盖车/炮/马/兵卒/帅的攻击检测（相/仕
   活动范围攻击不到对方九宫，不纳入）；行棋方无任何合法着法时，被将军为
   **将死**、未被将军为**困毙**——中国象棋中困毙判负非和棋。
4. **本地悔棋**：确认弹窗后撤销最近一步（恢复起点棋子与被吃子、行棋方回退），
   无子可悔按钮禁用；终局后按钮替换为「再来一局」。
5. **存档与恢复**：存档保存盘面编码 + 走子序列；恢复时从初始局面**正向重放
   走子序列**还原棋盘，重放终局面与盘面编码不一致视为存档损坏 → 删除该档。
   退出走统一三分支（保存并退出/不保存退出/取消），恢复后未走子退出不打扰。
6. **繁体文案**：棋子帥/將、仕/士、相/象、馬、車、炮、兵/卒，河界「楚河」「漢界」，
   将军提示「將軍」大字闪屏。

## 联机对战

**架构：房主权威 + 提交—校验—广播**。房主全量校验（坐标边界 → 轮次 → 起点
己方棋子 → 合法着法，逐层拒绝）后生效并广播，走子后用与本地同一规则引擎判定
将死/困毙；客户端只做最低一致性校验（起点有子且轮次匹配），矛盾广播直接应用
会静默破坏局面且无重同步手段 → 数据异常终局。页面骨架委托
`OnlineGamePageShell`，悔棋/认输协商委托 `BoardGameOnlinePageMixin`（棋类通用
唯一实现）。

**协议消息**（NDJSON TCP，信封 `{v, type, payload}`，协议版本 2）：

| 消息 | 方向 | 载荷 |
| --- | --- | --- |
| `moveSubmit` | 客户端 → 房主 | `fromCol/fromRow/toCol/toRow` |
| `moveResult` | 房主 → 提交者 | `ok`；拒绝时 `reason`（`notYourTurn`/`invalidMove`） |
| `moveApplied` | 房主广播 | 走子四坐标；将死/困毙时附加 `winner`（座位）与 `reason`（`checkmate`/`stalemate`） |
| `undoRequest` / `undoResponse` / `undoApplied` | 协商三方消息（棋类通用） | 发起快照手数 / 是否同意 / 回退目标手数 |
| `resign` | 声明方 → 房主 | 空（认输为单方声明，房主判对方获胜并广播） |
| `gameOver` | 房主广播 | `reason: 'resign'` + `winner` |

**悔棋协商（棋类通用状态机）**：只能悔自己的上一手，**轮到对方走子时才可发起**；
发起时快照目标手数，协商期间对方又走子的，同意后一并回退到快照；房主校验快照
末手确为请求方所下（防「悔对方的子」）。回退实现为**从初始局面正向重放走子
序列整体重建棋盘**——被吃子自然复原，双方执行同一确定性过程；客户端同意悔棋
也不动棋盘，回退统一以广播为准。

**座位与视角**：创建者（房主，座位 1）执红先行，加入者执黑；行棋方由手数奇偶
推导避免独立状态失同步。执黑方整盘旋转 180°（自己的棋子显示在屏幕下方，
棋子汉字朝向不变，河界两词位置对调）。联机对局不落本地存档；任一方中途退出/
断线对局直接结束（不判胜负，走通用终局弹窗）；再来一局联机暂未支持。

## 注意事项（重要坑点）

1. **可变棋盘是有意设计**：对局页集中持有状态，走子只搬两格、悔棋 revertMove
   即可，无需整盘重建；联机侧因悔棋需整体重放，棋盘字段不可 final。
2. **`movesFor`/`legalMovesFor` 显式判空而非 assert**：release 下 assert 被剥离，
   `piece!` 会抛 null check 异常。
3. **越界坐标必须在消息解析层拦截**：流入棋盘搬运会触发越界异常；`_isOwnLegalMove`
   必须先判起点有子，起点无子时 `legalMovesFor` 会断言失败。
4. **客户端不可信**：本地先拦一层非法提交只为省一次网络往返，房主对全部规则
   重做校验。
5. **走子动画序号单调递增不复位**：相同起终点的走法先后发生时走法记录相等，
   仅靠走法判等会漏触发动画。
6. **回退类局面变化不播滑行动画**（悔棋/重开/恢复）：回退语义与前进滑行观感
   不符；回退路径也不递增将军闪屏触发器——回退是协商结果而非新走子。
7. **被吃棋子动画期间垫底绘制在终点位**：消失瞬间已被移动棋子完全覆盖，观感
   是「被吃掉」而非凭空消失。
8. **点击命中为吸附式有意设计**：整个棋盘面（含留白）点击都命中最近交点，
   利于粗手指点选边线棋子；外框以外返回 null。
9. **存档恢复用重放而非 decode**：`ChessBoard.decode` 仅作编码逆向工具保留供
   测试，生产恢复链路走「重放走子 + encode 对比」双保险。
10. **本地认输首版不实现**：`ChessEndReason.resign` 仅联机协商使用，本地无该入口。
