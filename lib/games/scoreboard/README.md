# 计分器（scoreboard）

本地运动计分板工具：红蓝双方点击加分、自动判定局胜/场胜、支持撤销与
存档恢复。无内置项目预设——三项参数（赛制局数 / 每局胜利分 / 领先分差）
完全可配，以此适配主流项目（默认「BO3 · 每局 21 分 · 领先 2 分胜」即
乒乓球/羽毛球式计分）。**纯本地工具，无联机对局**。计分阶段进入横屏
全屏沉浸视图（无顶栏），设置阶段为竖屏。

## 文件结构

| 目录/文件 | 职责 |
| --- | --- |
| `models/` | `scoreboard_game_state`（计分存档模型：计分配置、当前比分、撤销快照栈，`version = 1`；实现 `GameArchiveSummary`） |
| `pages/` | `scoreboard_page`（持有整场计分状态：加分与胜负判定、局/场胜利弹窗、撤销、退出确认与存档恢复；阶段一竖屏设置、阶段二横屏全屏计分） |
| `services/` | `scoreboard_rules`（规则引擎：纯静态逻辑，局胜/场胜判定收敛于此，页面只管状态与交互）、`scoreboard_storage`（存档服务，`gameId = '计分器'`） |
| `widgets/` | `scoreboard_setup_view`（恢复入口 + 赛制/每局胜利比分/领先规则输入）、`scoreboard_view`（横屏红蓝计分板：两侧大数字点按加分、中央局间大比分牌，内部含队伍面板与比分牌私有组件） |

## 计分规则

1. **赛制为 BO 多数局**：赢下整场所需局数 `gamesToWin(bestOf) = bestOf ~/ 2 + 1`
   ——BO3 需赢 2 局、BO5 需赢 3 局；**仅允许奇数局数**（偶数局打满可能平局，
   无法产生整场胜方）。
2. **每局胜负**：先到达胜利分**且**满足领先分差的一方赢下本局
   （`score >= winScore && score - opp >= leadBy`）。
3. **平分决胜（deuce）**：无专门平分状态，由领先分差条件隐式实现——`leadBy`
   为 0 即「到分即胜」，为 2 即乒乓球/羽毛球的 deuce 规则；高分段延长赛
   （如 15:14）同样需 2 分差。
4. **点击计分**：加分前先快照入栈（红局/蓝局/红分/蓝分四元组）再加分判定；
   满足局胜 → 该方局分 +1 并弹「X方赢下本局」（下一局/继续查看）；局分达
   多数局 → 弹「X方获得胜利」（再来一场/返回设置/查看比分）并**立即清除存档**。
5. **下一局**：只清空当前局小比分，局分与快照栈保留（撤销可跨局回退）。
6. **撤销**：弹出最近快照恢复四元组并同步清除局/场结束状态——快照法天然支持
   跨局撤销（含撤销已判定的局胜/场胜）。
7. **存档/恢复**：退出走统一三分支；持久化完整状态（含撤销栈）；恢复双入口
   （设置页恢复卡 + 存档管理页「开始」）共用同一应用逻辑；恢复后未产生新计分
   动作就退出时存档保持原样（净零变化比对，含「加分又撤销」）。

## 参数速查

| 参数 | 值 | 位置 |
| --- | --- | --- |
| 默认赛制 / 每局分 / 领先分差 | BO3 / 21 / 2 | `ScoreboardSetupView.bestOfDefault` 等 |
| 赛制输入范围 | 1 ～ 31（仅奇数） | `ScoreboardSetupView` |
| 每局胜利分范围 | 1 ～ 99 | `ScoreboardSetupView` |
| 领先分差范围 | 0 ～ 9 | `ScoreboardSetupView` |
| 红蓝队伍色 | 红 `0xFFE5484D` / 蓝 `0xFF3E63DD`（体育计分惯例固定色，不随主题） | `ScoreboardView` |
| 存档格式版本 | 1（旧档缺失该字段视为 1） | `ScoreboardGameState.version` |

## 注意事项（重要坑点）

1. **gameOver 必须入档**：不保存会导致恢复后首次点击计分区走加分分支而非
   「开下一局」，错误重复判分；该字段为后加入字段，旧存档缺失时按「局进行中」
   处理保持兼容。
2. **整场分出胜负后立即清除存档**：无论后续选哪条路径（再来一场/返回设置/
   查看比分），都不能让已结束的比分被当作进行中对局恢复；清档失败仅留调试
   线索，残留存档无害（下次进入提示恢复已终局比赛，开新局即覆盖）。
3. **横屏 SafeArea 坑**：横屏系统栏/挖孔仅出现在一侧，直接用 SafeArea 会造成
   红蓝计分区不等宽——取左右避让最大值对称应用保证两侧等宽。
4. **进入页面即锁定竖屏**：避免携横屏状态进入设置视图。
5. **弹窗在 setState 之后调用**：避免构建期间弹 showDialog 抛框架错误。
6. **输入范围控制在两位数**（bestOf ≤ 31、winScore ≤ 99）：避免异常大数值
   影响计分板排版；非法输入保持上次生效值（与红边提示语义一致）。
7. **计分板大数字用 FittedBox** 防止小尺寸横屏下溢出；纯色底上用白色半透明
   水波纹。
8. **红蓝为体育计分惯例固定色**，不随主题强调色变化（与象棋棋子素材色
   同一处理思路）。
