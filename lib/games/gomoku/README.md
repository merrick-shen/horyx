# 五子棋（gomoku）

黑白轮流落子、先连成五子者胜的双人对弈：横、竖、两条斜线任一方向连成
5 子及以上即胜（六连及以上同样判胜，长连不禁手）。棋盘规格可选 9 路 /
15 路（默认）/ 19 路，共用组件 `StoneBoard`（`CustomPaint` 自绘网格线、
星位与棋子，木色系固定配色）正方形自适应。支持本地双人同屏与局域网
2 人联机（房主权威校验落子 + 棋类通用悔棋/认输协商）。确认落子配提示音，
经共享音频门面 `GameAudio` 播放（见 `lib/shared/audio/`）。

## 核心流程

1. **设置**：选棋盘规格（9/15/19 路，默认 15）与模式；存在存档时展示恢复入口
   （设置页恢复卡 + 存档管理页「开始」定点恢复双链路）。
2. **落子确认（两段式）**：点击交叉点更新预选（已占点不可选）→ 确认行
   「取消/下棋」→ 确认后预选转正式落子并播放落子音。
3. **执子方推导**：落子序列索引奇偶决定颜色——偶索引黑方先手；胜方座位亦由
   手数奇偶推导，避免独立状态失同步。
4. **五连判定**：四方向（横/竖/两斜）沿正负两方向延伸计数，`count >= 5` 即胜；
   判定前构建「位置 → 是否黑子」索引，整体 O(n)（19 路满盘 361 手亦瞬时完成）。
5. **本地悔棋**：确认弹窗后撤回最后一颗棋子（占位集合同步移除、执子方回退），
   无子可悔按钮禁用。
6. **胜负处理**：五连即置胜方并**立即清除存档**（避免重进恢复出已结束局面），
   弹窗三选项（再来一局/返回设置/取消留守查看棋型）。
7. **退出与存档**：对局中拦系统返回走三选项确认；恢复后与基线比对一致（含
   悔棋净零变化）视为无新进度，存档保持原样；无平局/满盘终局逻辑——胜负
   唯一来源是五连。

## 联机对战

**架构：房主权威 + 提交—校验—广播**。客户端本地先拦明显非法（未轮到/已占，
省一次网络往返），房主收到提交后**全部规则重做校验**（轮次 + 落点），通过回执
并广播、拒绝单独回执原因；客户端不自行判定合法性，仅做最低一致性校验（落点
在盘内且未重复），矛盾广播走数据异常终局而非静默应用。悔棋/认输协商接入棋类
通用混入（gomoku/chess 共用唯一实现），页面骨架委托 `OnlineGamePageShell`。

**协议消息**（NDJSON TCP，信封 `{v, type, payload}`，协议版本 2）：

| 消息 | 方向 | 载荷 |
| --- | --- | --- |
| `gameStart` | 房主广播 | 人数与座位顺序，**五子棋额外携带 `boardSize`**（客户端据此构建同规格棋盘） |
| `stoneSubmit` | 客户端 → 房主 | `col` + `row` |
| `stoneResult` | 房主 → 提交者 | `ok`；拒绝时 `reason`（`notYourTurn`/`occupied`） |
| `stoneApplied` | 房主广播 | `col` + `row`；五连时附加 `winner`（座位） |
| `undoRequest` / `undoResponse` / `undoApplied` | 悔棋协商三方消息（棋类通用） | 发起快照手数 / 是否同意 / 回退目标手数 |
| `resign` / `gameOver` | 认输声明 / 房主广播 | 认输为单方声明，房主判对方获胜并广播 `gameOver {reason: 'resign', winner}` |

**音效**：`stoneApplied` 生效全端播落子音（房主在 `_applyStone`、客户端在广播
处理处，经 `GomokuAudio` 委托共享门面 `GameAudio`）；悔棋回退与终局不配音
（胜利/终局类音效已确认不做）。

**悔棋协商**：只能悔自己的上一手，仅对方回合可发起；发起时快照手数，房主校验
快照末手确为请求方所下；同意后房主 `removeRange` 回退并广播，双端同步回退到
快照（含协商期间的新增落子）；客户端同意悔棋也不动棋盘，回退统一以广播为准
（避免与应答双回退）。

**座位与执子**：创建者（房主，座位 1）执黑先行，加入者执白；当前执子座位由
落子数奇偶推导。联机对局不落本地存档；任一方中途退出/断线对局直接结束（不判
胜负，走通用终局弹窗）；再来一局暂未支持，终局后仅提供退出对局。

## 注意事项（重要坑点）

1. **规则引擎两侧同源**：本地页与联机控制器共用 `GomokuRules`——此前两份独立
   实现行为一致，但改规则时会静默分叉。
2. **占位集合必须与落子序列同步增删**（悔棋/恢复/清盘处），否则五连判定失真。
3. **客户端棋盘规格非法时不得静默回退 15 路**——静默回退会导致双端棋盘不一致；
   兜底规格仅用于终局弹窗前的空棋盘渲染，随即数据异常终局。
4. **矛盾广播不静默应用**：静默污染落子序列会让回合奇偶推导、执子卡、渲染
   全部失真，走数据异常终局。
5. **棋盘固定木色系双套配色**：底色曾用主题色——浅色主题与白子同色、深色主题
   与黑子同色，棋子只剩描边可辨；棋子固有色不随主题，仅描边随主题取色。
6. **边距取半格的理由**：恰好容纳边线棋子（半径 0.42 格），更大边距在 19 路
   等密路数下浪费宽度、棋盘显小。
7. **Stone 颜色显式存储而非奇偶推导**：为提子等无法从奇偶推断黑白的规则场景
   预留；五子棋无提子，序列奇偶即可推导。
8. **迟到的落子提交在对局结束后被房主忽略**；`undoApplied` 目标缺失/非法时
   兜底退一手（同版本协议下不会走到）。
9. **音效静默降级**：播放经共享门面 `GameAudio`（全项目唯一 SoLoud 触达点），
   引擎初始化失败或素材未就绪时静默跳过、绝不影响对局；音效在对局页
   initState 后台预载，进页后极短窗口内落子可能无声属预期行为。
